# Ocean: the interface and the inference runtime

Ocean combines a web conversation interface with backend services that route requests to an inference provider. Updating one part does not automatically update every other part of the system.

## Conversation interface

The Curiosity Ocean module includes a conversation view, a message composer and controls for attached documents, camera capture and voice interaction. A dedicated voice route supports the voice conversation experience. These controls depend on the corresponding runtime services; a visible button alone is not evidence that the underlying capability is available.

The web application sends conversation requests through server routes. Streaming responses require those routes, the backend and the proxy to agree on the response protocol. Errors and missing capabilities must remain visible rather than being replaced with invented results.

## Language model selection

The inference runtime can be configured independently from the browser interface. Provider configuration selects where model requests are sent, and the serving process determines which model is actually loaded. A configured name is not sufficient evidence of a completed inference or a particular performance level.

For this reason, an operational audit should compare the configured provider and model with the model server's running-process inventory and actual request results. Model names, quantization and context configuration belong in that audit rather than being assumed from UI branding.

## Releases and evidence

A local source change, an integrated Git commit, a published container image and a running production container are separate states. Release verification needs to identify the exact artifact serving traffic and exercise the affected behavior. A healthy container confirms only its health check; it does not establish conversation quality or the correctness of every feature.

This is an architectural explanation of the source implementation, not a claim of measured accuracy, availability, throughput or medical suitability.
