# Independent document publishing on GitHub Pages

Clisonix publishes its document hub on GitHub Pages. The archive, category index, individual articles, RSS feed and sitemap are static files in the existing blog repository. Reading the blog requires neither a Hetzner database nor LinkedIn credentials.

## Reviewing new documents

New engineering documents are listed in a publication manifest with their public identifier, classification and the SHA-256 digest of their reviewed source bytes. The static publisher checks each digest before producing public files. A source edit with an unchanged approval digest fails publication rather than silently accepting a different document.

The scheduled publication job reads accepted documents from the platform's main branch. It updates the existing GitHub Pages repository using that repository's own GitHub Actions credentials and requests a Pages build. It does not copy a personal GitHub token onto the application server.

## Restoring the archive

The document hub reads its categories and articles from generated JSON files served beside the website. Article detail is available as JSON for the reading dialog and as a permanent HTML page. The March interface retains its document categories, authors, search, sorting and pagination.

Historical source posts retain their dates and contents. Rebuilding the archive does not turn a historical scientific statement into newly validated evidence. Generated medical articles waiting on an application server require separate review before becoming newly approved publications.

## Evidence and limits

Publication success requires a real commit and a successful Pages deployment, followed by checks of the public index, article links and content. A scheduled job, generated file count or configured publication interval alone does not prove successful public delivery. No measured throughput or availability claim is made here.
